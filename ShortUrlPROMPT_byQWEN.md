# Роль
Ты — опытный Fullstack-разработчик и DevOps-инженер (Python/Vue), специализирующийся на архитектуре микросервисов, паттернах проектирования и контейнеризации. 

# Задача
Разработать полнофункциональное приложение "Сократитель ссылок" (URL Shortener) с разделенными фронтендом и бекендом. Проект должен быть упакован в Docker-контейнеры и объединен через Docker Compose с использованием лоад-балансера.

# Стек технологий
- **Бекенд:** Python, FastAPI, Redis, SQLAlchemy, Alembic, PostgreSQL, Pydantic.
- **Фронтенд:** JavaScript (ES6+), Vue.js (Composition API), Vite.
- **Инфраструктура:** Docker, Docker Compose, Nginx (Load Balancer / Reverse Proxy).

# Функциональные требования
1. **Авторизация и регистрация:** Хранение пользователей и их данных в PostgreSQL.
2. **Неавторизованные пользователи:** 
   - Могут создавать сокращенные ссылки.
   - Ссылка возвращается в текстовом виде и в виде сгенерированного QR-кода.
3. **Авторизованные пользователи:**
   - Могут создавать ссылки (возврат в текстовом виде + QR-код).
   - Имеют доступ к минимальной аналитике: время переходов, общее количество кликов, источник перехода (Referer), если это возможно.
   - Могут сами выбирать TTL (время жизни) для своих ссылок или делать их вечными.

# Строгие бизнес-правила (ОБЯЗАТЕЛЬНО К ИСПОЛНЕНИЮ)
1. Ссылки неавторизованных пользователей хранятся **ТОЛЬКО В REDIS** с фиксированным TTL.
2. Если неавторизованный пользователь пытается сократить длинную ссылку, которая уже существует в Redis, система должна вернуть **УЖЕ СУЩЕСТВУЮЩУЮ** сокращенную ссылку, а не создавать новую.
3. Для всех HTTP-ошибок использовать стандартные коды из модуля `fastapi.status` (например, `status.HTTP_404_NOT_FOUND`, `status.HTTP_400_BAD_REQUEST`).
4. **Валидация URL:** Нельзя добавить ссылку, которая технически не может существовать (например, `http://asfasf`, `www.somedomain.ashgiasoghgiaso`). Реализуй строгую проверку синтаксиса и доступности домена (например, через проверку DNS или HTTP HEAD запрос).
5. Ссылки и статистика авторизованных пользователей хранятся **ТОЛЬКО В PostgreSQL**.
6. **Дизайн фронтенда** должен быть строго выполнен в стиле **Glassmorphism** (стекломорфизм: полупрозрачные фоны с размытием, тонкие границы, тени).

# Структура проекта
Проект должен строго соответствовать следующей структуре папок. Не отклоняйся от неё:

    /url_shortener_project/ 
    /backend:
        /src:
            /models (SQLAlchemy модели таблиц для PostgreSQL)
            /schemas (Pydantic схемы для валидации входных/выходных данных)
            /database:
                /redis (настройка клиента и CRUD операции с Redis)
                /postgre (настройка сессий, двигателя и базовые CRUD хелперы для PostgreSQL)
            /api:
                /v1 (APIRouter'ы для каждой зоны ответственности: auth, links, stats. Объединяются в main.py)
            /service (слой бизнес-логики, вызываемый из /api/v1)
            /repository (слой взаимодействия с БД, использующий функции из /src/database)
            /utils (утилиты: генерация коротких хэшей, создание QR-кодов, валидация URL)
        /alembic (инициализация, env.py и скрипты миграций БД на основе /src/models)
        /docs (документация к бекенду, например, README.md)
    /frontend:
        /app (структура фронтенда строго по методологии Atomic Design: /atoms, /molecules, /organisms, /templates, /pages)
        /docs (документация к фронтенду)

# Дополнительные требования
1. Разрешается устанавливать дополнительные библиотеки по своему усмотрению (например, `qrcode` для генерации QR, `validators` или `tldextract` для проверки URL, `slowapi` для rate limiting).
2. **Rate Limiter:** Добавить ограничение частоты запросов (Rate Limiting) на уровне API для защиты от спама (например, ограничить создание ссылок неавторизованными пользователями).
3. **Load Balancer:** Настроить Nginx в Docker Compose в качестве балансировщика нагрузки. Бекенд должен быть запущен в нескольких репликах (например, через Gunicorn с воркерами или несколько контейнеров в композе), а Nginx должен балансировать трафик между ними и отдавать статику фронтенда.

# Формат ответа
Предоставь решение пошагово:
1. **Архитектура и Инфраструктура:** Напиши полный `docker-compose.yml` и конфигурацию `nginx.conf` (с настройкой проксирования, балансировки и rate limiting на уровне Nginx, если применимо).
2. **Бекенд (Backend):** Предоставь код для всех ключевых файлов согласно структуре (models, schemas, database, api, service, repository, utils, main.py). Особое внимание удели слою `service` и логике проверки существующих ссылок в Redis.
3. **Фронтенд (Frontend):** Напиши базовую структуру Vue 3 + Vite с примерами компонентов в стиле Glassmorphism (CSS с `backdrop-filter: blur`, полупрозрачностью и тенями) по методологии Atomic Design.
4. **Инструкции:** Кратко опиши, как запустить проект, применить миграции Alembic и протестировать API.

Пиши чистый, production-ready код с комментариями и правильной обработкой исключений (try/except).
